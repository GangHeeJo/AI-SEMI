# 키프레임(SLAM) 방식 -- 사전 등록 평가 기준 (2026-10-27, 코드 작성 전에 커밋)

질문: 이벤트를 월드 메모리에 바로 누적하는 현재 방식 대신, 키프레임 이미지 + 1차원 자세 그래프 + 루프 클로저로
바꾸면 (1) 각도 오차와 (2) 지도 품질이 좋아지는가, (3) 메모리 비용은 얼마인가.

## 시험 조건 (소프트웨어, 정답 각도를 아는 합성 데이터; 결과를 본 뒤 바꾸지 않음)
- 장면: 반지름 128 px 원판 안의 무작위 선분 40개 + 점 60개, 깊이 하나(시차 없음). 센서 패치 256x256, 회전중심 = 패치 중심.
  (한계: 실제 DELTA의 깊이별 회전중심 시차, 봉-피벗 원호 이동은 이 시험에 없음.)
- 이벤트: 선분 위 무작위 점, 에지 법선 방향 속도에 비례해 채택, 위치 잡음 0.6 px, 배경 잡음 3%, 창(2 ms) 안에서 참 시각의 각도로 생성.
- 이벤트율: 주 조건 400개/ms, 민감도 조건 100개/ms(통과 판정에는 주 조건만 사용).
- 각도 프로파일(참값): P1 0->170도 한 방향(대조군, 재방문 없음), P2 0->120->0->120도 왕복, P3 0->170->40->170도. 시드 0,1,2.
- 방법:
  B0 = 창 대 창 각도 적분(드리프트 하한 참고용), B1 = 창마다 누적 월드맵과 정합(현재 설계에 해당, 인과적),
  K-fine = 키프레임 간격 0.45도 + 자세 그래프 + 루프 클로저, K-coarse = 간격 3도 + 이벤트별 작은 각도 보정 + 자세 그래프 + 루프 클로저.
- 추적 탐색: 예측 각도(등속, EMA 0.5) 주위 +-2.5도, 0.25도 간격. 점수 = 이벤트를 회전해 가우시안(sigma 1.5 px) 블러 맵에 떨어뜨린 값의 합.
- 루프 클로저 수락 규칙(고정): 키프레임 쌍 정합 NCC >= 0.5 이고 2등 봉우리 대비 1.5배 이상. 후보 = 현재 추정 각도 차 10도 이내이면서 인덱스 차 > 5.
- 각도 오차는 t=0 에서 0으로 고정(게이지)한 뒤 참값과의 차이.

## 판정 기준
- C1 정확도(P2,P3, 3시드 = 6회, 주 조건): K의 최대 |각도 오차| / B1의 최대 |각도 오차|의 중앙값 <= 0.5, 그리고 어느 회차도 비율 > 1.0이 아님.
- C2 대조군(P1, 3시드): K의 최대 오차 <= 1.2 x B1의 최대 오차 (해를 끼치지 않음).
- C3 지도(P2,P3, 6회): 잔상 질량(참 선에서 3 px 밖 비율)이 B1 이하인 회차가 5/6 이상, 커버리지(참 선 픽셀 중 2 px 안에 지도 질량이 있는 비율) 하락은 2%p 이내.
- C4 비용: 키프레임 총 비트(256x256x2비트 x 180도를 덮는 개수) <= 현재 월드 메모리(1024x1024x2비트 = 2,097,152비트)의 4배 = 8,388,608비트.
  (K-fine: 400장 = 52.4 Mbit로 미리 계산상 실패, K-coarse: 60장 = 7.86 Mbit.)
- C5 루프 클로저 건전성: 수락된 루프 클로저 중 참값 대비 오차 > 1도인 것이 모든 회차에서 0개, 그리고 P2/P3 각 회차에서 참 루프 클로저가 1개 이상 수락됨.
- 결론 규칙: K 설정 중 하나가 C1~C5를 모두 통과해야 "설계 방향으로 채택 검토". 하나라도 실패하면 어느 기준이 실패했는지를 그대로 기록하고 기각/보류.
- 시험 후 규칙/임계값 조정이 필요하면 조용히 고치지 않고 새 변형으로 이름 붙여 별도 사전 등록한다.
